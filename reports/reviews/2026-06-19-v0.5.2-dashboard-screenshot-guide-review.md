# Release Readiness Review - portfolio-risk-compass v0.5.2

Date: 2026-06-19 CST
Increment: dashboard-screenshot-guide
Decision: PASS for local release candidate; no workflow or push changes made.

## Scope

- Added a deterministic `screenshot-guide` CLI artifact for the static public dashboard route.
- Included JSON and Markdown generated outputs:
  - `examples/outputs/dashboard_screenshot_guide.json`
  - `examples/outputs/dashboard_screenshot_guide.md`
- Tied the guide to `dashboard.html` and `public_review_walkthrough.md`; the visual evidence receipt links back to the guide without creating a hash cycle.
- Recorded exact Chromium screenshot capture instructions, viewport, output path, source hashes, screenshot hash slot, and no-live-data/no-broker/no-advice boundaries.
- Clarified that "public" means generated demo/review artifacts intended for sharing after review, not private holdings, account exports, or screenshots with account identifiers.
- Bumped package version from `0.5.1` to `0.5.2`.

## Release Evidence

- Version metadata should align between `pyproject.toml` and `src/portfolio_risk_compass/__init__.py`.
- Release artifact inventory should be regenerated through `portfolio-risk-compass release-manifest`.
- Docs export should be regenerated through `portfolio-risk-compass docs-export`.
- Screenshot guide is deterministic before and after screenshot capture: missing screenshot outputs are reported as missing until the exact capture command is run, then SHA-256 hashes are recorded.
- Public review hashes dashboard/review evidence only; screenshot guide hashes the public walkthrough, and the visual evidence receipt links both artifacts without creating a public-review/screenshot-guide hash cycle.
- Safety boundary remains static local artifact review only: no broker connectivity, no live market data, no order entry, and no investment advice.

## Residual Risk

- The guide records exact screenshot capture instructions and hashes but does not add Playwright as a package dependency.
- A screenshot binary is not committed by default; reviewers generate it locally when visual evidence is needed.
- Isolated `python -m build --sdist --wheel` was not available because the `build` module is not installed; isolated `pip wheel` could not fetch build dependencies under restricted network, so packaging was verified with no-build-isolation wheel creation.
